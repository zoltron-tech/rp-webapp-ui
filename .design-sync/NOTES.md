## Lib forks (.design-sync/overrides/, declared in cfg.libOverrides)
- bundle.mjs: (1) tsconfigPathsPlugin must skip directory hits (barrel imports like "@/context" resolved to the dir, esbuild EISDIR) — statSync isFile check; (2) banner defines a browser `process` shim (deps read bare `process` beyond the NODE_ENV define; without it every preview throws "process is not defined").
- source-kit.mjs: synth entry excludes non-canonical duplicate-export files (edit-storyboard-event/index.tsx + fandom-select.tsx, friend-list-item/page.tsx, event-thread-input/sent-button.tsx) — ambiguous star re-exports get dropped by esbuild and land undefined on the window global.
- dts.mjs: props ts-morph project also loads src/**/*.{ts,tsx} with the @/* alias and hunts the component symbol across src for local `Props` aliases — synth repos have no shipped .d.ts; stock lib emitted 224 stub contracts, fork gets 196 real ones (28 stubs remain: styled-only/odd exports).

## Other gotchas
- Default-only exports (`export default function X`) never surface through `export * from` — canonical-exports.ts (extraEntries) re-exports 13 of them (data cards, tour guides, PWAInstallButton, plus canonical picks for the 4 duplicate names).
- Any non-null componentSrcMap entry suppresses the src-derive discovery fallback (component list collapses to just the map) — leave componentSrcMap EMPTY in synth mode.
- CSS: cfg.cssEntry = .design-sync/flattened.css, generated by `node .design-sync/tools/flatten-css.mjs` (inlines @radix-ui/colors + @novelist-world/ui styles + toastify + globals.css, rewrites font urls). RE-RUN flatten-css after changing globals.css or upgrading those packages.
- Theme: DSProvider (extraEntries + cfg.provider) mirrors src/app/rp/layout.tsx: styled-components ThemeProvider(THEME_DARK+DefaultTheme) → StoreProvider(global-store initial) → Auth/Socket/UI/Music providers → div.page-container.dark.jade with background var(--bg-1). Wrapper must NOT set minHeight/padding — either defeats the floor-card collapse heuristic (empty renders must measure <2px tall).
- Fonts: 9 families, 54 files shipped from src/assets/fonts via globals.css @font-face.
- Preview authoring: import from 'rp-webapp'; esbuild does not type-check previews; runtime field reads are what matter (match nested type shapes: Message.repliedTo = {type:"MESSAGE", message: Message}, avatars read .image/.firstName.charAt). SVG data URIs for images.
- Form-context components (PasswordField, Prompt*Field, EventThread*Input...) throw "`FormField` must be used within `Form`" — Form lives in @novelist-world/ui and is NOT a bundle export; compose inside an exported parent or leave floor card.
- NovelistCard needs Swiper slide context — compose inside NovelistCarousel.
- HomeTourGuide/ProfileTourGuide: "Maximum call stack size exceeded" in preview (react-joyride under stub router?) — floor card for now.

## Component gotchas (from preview authoring, reusable on any re-sync)

- Fixed-position overlays (Modal, MiniMuseCard, MiniProfileCard) don't escape the card — the story root has `transform:translateZ(0)`, so `position:fixed` descendants use it as containing block. Give an in-flow spacer `<div style={{height: N}}/>` as a sibling. These 3 also need `cfg.overrides.<Name>: {"cardMode":"single","primaryStory":"<best export>"}` — set in config.json.
- `cfg.overrides` also holds `{"cardMode":"column"}` for Dropdown, ButtonGroup, ExpandablePill — their stories render wider than the product's grid cell.
- Modal open state: it hardcodes `visible=false`; open via `window.dispatchEvent(new Event("visibility-provider:open:<name>"))` in a `useEffect` on a sibling rendered AFTER the Modal (listeners must mount first — same ordering rule applies to any VisibilityProvider-backed component).
- common `Card` is a size container (`container-type:size`) — 0-height unless given explicit width/height.
- common `Input`: don't pass a custom `placeholder` on an empty field — the floating label overlaps it.
- `ExpandablePill` needs a `containerName:"profile-content", containerType:"inline-size"` ancestor, and its scroll-content avatars need `rotate(90deg)` counter-rotation.
- common `Dropdown`'s surface is `height:0` by design (open state only flips opacity) — give the child panel its own background/border.
- `PasswordField`/`UpdatePasswordFields` throw `` `FormField` must be used within `Form` `` — `Form` (from @novelist-world/ui) isn't a bundle export. Currently shipping a stand-in composition (legacy Input + PasswordChecks), graded as such. Fix: add `export { Form } from "@novelist-world/ui"` (or equivalent) to canonical-exports.ts, then re-author.
- Same `Form`-context crash hits: FandomSelect, EventThreadMediaInput, EventThreadTextField, PromptPrivacySelect, PromptInputTrigger (`CollapsibleTrigger` needs `Collapsible`), PromptMediaInput, PromptTextField, UpdatePasswordFields — all floor-carded pending the same Form-export fix.
- `Card.d.ts`'s auto-extracted contract is wrong (`{banner: string}` — bound the wrong same-name symbol); real API is children + width/height/margin/padding/centered. Cosmetic (previews aren't type-checked) but misleads a design agent reading the `.d.ts`. Fix with `cfg.dtsPropsFor.Card` on a future sync.
- `Pill` (src/components/common/pill, a bare styled.div) has no component card at all — not in the converter's discovery, nothing to author against.
- `PromptSongPlayer` returns `null` unless `song.url` is set — use a data-URI silent WAV (`data:audio/wav;base64,UklGRiQAAABXQVZFZm10IBAAAAABAAEAQB8AAEAfAAABAAgAZGF0YQAAAAA=`) to show the featured-song pill on Prompt.
- `PromptContent` only renders `media` when the string starts with `http` (data URIs silently no-op there; Comment's media has no such guard).
- `ExpandablePill` hides its label entirely when `expandable={false}`.
- Capture cells clip tall vertical stacks (~1000px cap) — keep FriendListItem-style stacks to ~2 items.
- `NovelistCard` needs Swiper slide context (`useSwiperSlide`/`useSwiper`) — only renders inside `NovelistCarousel`; floor-carded (composing via the carousel requires seeding the global `novelists` list, not attempted this sync).
- `ProfileCard` (`src/components/profile-card`) — **app bug, not a sync artifact**: `ProfileCardProps = {}`, component always returns `<Card>Profile Card</Card>` regardless of fetched data. Worth a look outside this sync.
- `useGlobalStoreSet`/`useGlobalState` added to canonical-exports.ts so previews can seed global-store state (novelist, novelists, etc.) — but seeding-then-reading in the SAME preview mount was unreliable in testing (NovelistPreviewCard's connection-state cell never picked up a seeded `novelist`, even after fixing effect ordering and a real Windows-path-separator bundler bug — see below). Treat store-seeding as unverified; prefer prop-driven variance where the component supports it.
- **Bundler bug fixed**: `bundle.mjs`'s `tsconfigPathsPlugin` returned Windows backslash paths from `path.join()`; esbuild's own resolver returns forward-slash paths, so any `@/`-aliased import competing with a same-file relative import could bundle as TWO separate module instances (silently duplicating singleton state — e.g. the store's React Context map). Fixed by normalizing to forward slashes before returning `{path}`. This was a real, bundle-wide correctness bug, not preview-only — worth carrying forward to any other `package-build.mjs` synth-entry sync on Windows.
- 3 unscoped components (asterism-styles/AsterismPreview, general/EditMuseAboutSectionForm, general/EditMusicForm) render non-crashing but visually near-empty (16-40px tall) — not floor-carded (root isn't literally empty) and not in the 41-component authored scope. Low-priority cleanup for a future sync.

## Upload gotcha (this tool, not the converter)

- One `write_files` call in the close-out (a 200-file chunk covering ~27 `components/general/*` dirs) reported `written: 200` but roughly half those files 404'd on `get_file` afterward — a silent partial failure with no error surfaced. Caught it by spot-checking `get_file` on a few paths per chunk rather than trusting the `written` count; fixed by re-pushing the missing dirs in two ~55-file chunks (both verified present after). **Lesson for future closeouts on this project: after any large `write_files` call, spot-check 1-2 arbitrary paths with `get_file` before trusting `written: N` — don't rely on the count alone.**

## Re-sync risks
- flattened.css is a snapshot: silently stales if globals.css, @radix-ui/colors, toastify, or @novelist-world/ui styles change — re-run flatten-css before every re-sync build.
- canonical-exports.ts + source-kit SYNTH_EXCLUDE list rot if the app renames/moves the duplicate-export files — a [BUNDLE_EXPORT] error on re-sync means re-audit those lists.
- Stubs pin app behavior (e.g. next/config returns empty publicRuntimeConfig): server actions fail soft in previews; components must keep rendering their loading/empty states for floor cards to stay honest.
- The 28 remaining stub .d.ts contracts (grep 'key: string' ds-bundle/components/*/*/[A-Z]*.d.ts) are mostly styled-exports; dtsPropsFor can fix individually if the design agent misuses one.
- Chromium cache pin: playwright 1.48.x ↔ chromium-1140; a playwright bump without browser install fails launch.
